# 第三单元讲义：可离线完成的钱包操作演练

对应课次：9～11

版本：2.0

资料核对日期：2026-09-01

建议用时：2.5～3.5 小时

> 本单元的必做部分不依赖水龙头、主网余额、第三方登录或 DApp。你可以用已创建的空练习钱包完成全部必做项。公共 Sepolia 收发改为可选加练：它能增加真实链上经验，但任何水龙头的可用性、限额或资格都不影响本单元是否通过。

## 先说清楚：本单元保证什么、不保证什么

| 项目 | 必做离线主线 | 可选 Sepolia 加练 |
| --- | --- | --- |
| 是否依赖第三方服务 | 否 | 是：依赖钱包、RPC、区块浏览器与水龙头 |
| 是否需要真实资金 | 否 | 否，禁止使用真实资金 |
| 是否生成或展示秘密 | 仅在钱包本地生成与恢复，绝不展示 | 同左 |
| 能训练什么 | 账户隔离、锁定、恢复、签名前核对与拒绝 | 真实网络、Gas、待确认与区块浏览器字段 |
| 是否是通关条件 | 是 | 否 |

没有任何课程能诚实保证第三方水龙头始终可用；它们会限额、要求主网历史、登录或临时故障。课程能保证的是：即使它失败，你仍能完成与安全最相关的操作和验收。

## 课次 9：把当前空钱包变成“练习钱包”

本课不转账、不连接网站、不领取测试币。

### 你要做什么

1. 只打开此前建立的隔离浏览器配置文件和新建的 MetaMask 钱包。
2. 在账户名称处把默认账户改名为 `练习 A - 永不上主网`；如界面不支持改名，写在自己的纸质笔记上即可。
3. 点击账户名旁的下拉箭头，选择 `Add account or hardware wallet`，再选择 `+ Ethereum account`。
4. 新账户命名为 `练习 B - 永不上主网`。这会在同一恢复短语下派生第二个 Ethereum 账户，不会发送交易。
5. 私下分别打开 A、B 的账户详情，确认它们是两个不同的 `0x` 地址。不要复制到聊天、日志或截图。
6. 锁定钱包，再用本地密码解锁一次。

### 你应该看到什么

- 有两个账户：A 和 B；
- 两者都是 `0x` 开头、彼此不同的 Ethereum 地址；
- 余额均为零是正常的；
- 锁定后重新打开钱包会要求本地密码，而不是恢复短语。

### 这一步学到什么

- 一个恢复短语可派生多个账户；
- 钱包密码负责本设备上的解锁，不替代恢复短语；
- 创建账户、复制地址、切换显示网络都不等于签署链上交易；
- 余额为零不表示钱包创建失败。

MetaMask 对“创建附加 Ethereum 账户”的官方说明见[这里](https://support.metamask.io/configure/accounts/how-to-add-accounts-in-your-wallet)。

### 停止条件

出现导入旧钱包、输入既有助记词、付款、连接网站、签名或“批准额度”时立即退出。这些都不是本课所需动作。

## 课次 10：离线练习“确认前必须看什么”

打开本仓库的[本地交易确认演练器](../../labs/stage-03-transaction-rehearsal.html)。它不联网、不读取钱包、不生成密钥，也不会发送交易；可反复练到你能一眼发现错误为止。

### 练法

1. 先完成一个正确的“Sepolia、A 到 B、少量测试 ETH、普通转账”请求；
2. 再逐个故意制造错误：主网、陌生收款方、`approve`、无限额度、未知 `data`；
3. 每次都要先说出拒绝理由，再点击演练器的“拒绝”或“确认”；
4. 只有在所有字段都符合预期时，才允许演练器显示“可确认”。

### 真实确认页的六句话

以后看到任何钱包确认页，先在心里逐句回答：

1. 这是哪个网络？我是否特意要在这里操作？
2. 谁在发起？是不是我的练习 A？
3. 收款方/合约是不是我从可信来源得到的目标？
4. 这是普通转账，还是调用合约、授权、permit 或消息签名？
5. 金额/额度、Gas 和有效期是否符合我的原意？
6. 有任何一项答不上来吗？有就拒绝。

离线演练器通过，只能证明你会审阅请求；它不会伪造“已经签过链上交易”的经历。

## 课次 11：恢复演练（本单元的核心验收）

恢复演练不需要余额，不需要测试网，也不需要删除原钱包。

### 准备

- 保留当前 A、B 钱包原样；不要卸载、重置或删除它；
- 新建第二个完全干净的浏览器配置文件；
- 从 MetaMask 官方入口安装同一钱包；
- 取出纸上保存的练习恢复短语，仅在本地 MetaMask 恢复界面使用。

### 你要做什么

1. 在第二个浏览器配置文件打开 MetaMask，选择 `I have an existing wallet` 或“导入/恢复钱包”。
2. 选择恢复短语方式，不选社交登录。
3. 只在 MetaMask 本地页面输入练习恢复短语；不复制给任何网站、聊天或“检查工具”。
4. 设置第二个配置文件专用的本地解锁密码。
5. 恢复完成后，私下核对恢复出的 Account 1 地址是否与 A 完全一致。
6. 查看账户列表：若 B 已由 `Backup and sync` 自动恢复，直接核对；若没有，再重复“添加 Ethereum 账户”操作，直到出现与 B 完全一致的第二个地址。
7. 回到原配置文件，确认 A、B 仍在；两个配置文件都不需要签名或转账。

### 为什么 B 可能自动出现，也可能需要手动添加

截至 2026-09-01，MetaMask 的 `Backup and sync` 默认启用；同一恢复短语下创建的账户可能自动同步。若该功能关闭或账户未被自动加入，没有余额的后续账户仍可能需要手动添加。无论走哪条路径，恢复后出现与原 B 完全相同的地址，才是验收依据。

### 成功标准

- 恢复后的 A 与原 A 完全一致；
- 自动恢复或手动添加后的 B 与原 B 完全一致；
- 两个账户仍为零余额也算成功；
- 全程没有把恢复短语、完整地址或截图发出。

MetaMask 的恢复说明指出，恢复后可能需要手动再添加账户才能找回后续账户；本练习利用这一点验证恢复过程。[官方说明](https://support.metamask.io/configure/wallet/how-to-restore-your-metamask-wallet-from-secret-recovery-phrase/)

MetaMask 的账户同步说明见[官方文档](https://support.metamask.io/configure/wallet/account-backup-and-sync)。

## 可选加练：真实 Sepolia 收发

仅当你想额外体验真实链上交易，且当天官方列出的水龙头可用时才做。水龙头失败、要求主网余额、登录、付款、签名或页面报错都不是你的错误，直接停止即可。

1. 从 [Ethereum 官方网络页](https://ethereum.org/developers/docs/networks/)当天列出的 Sepolia 水龙头进入；
2. 只填写 A 的公开 `0x` 地址；
3. 只接受免费、无签名、无主网余额要求的领取方式；
4. 若 A 收到测试 ETH，创建一个 A → B 的小额普通转账；
5. 确认页必须是 Sepolia、From 为 A、To 为 B、资产为测试 ETH，且没有合约 data、approve、permit 或消息签名；
6. 用官方页面列出的区块浏览器只读核对结果；
7. 水龙头不可用时，记录“外部服务不可用”，不要重试到疲劳、不要换用陌生社群链接、更不要使用真实资金。

Sepolia 仍是 Ethereum 官方列出的应用测试网，但水龙头资格与可用性是外部服务自行决定的动态事实。[官方网络页](https://ethereum.org/developers/docs/networks/)

## 单元检查

1. 创建 B 为什么不需要再次生成一组恢复短语？
2. 为什么 A、B 都为零余额仍能验证恢复是否正确？
3. 为什么先锁定—解锁，再做恢复演练？
4. 恢复后 B 没有自动出现时，为什么不能立刻判断恢复短语错误？
5. 普通转账确认页出现 `approve` 或未知 `data` 时该做什么？
6. 水龙头要求主网余额时为什么不能转入真实 ETH 来绕过？
7. 离线演练器能训练什么，又不能证明什么？

每题 0～2 分，至少 11/14；第 4～6 题不得为 0。

## 完成标准

- [ ] 已创建练习 A 与练习 B，且私下确认地址不同；
- [ ] 已完成锁定—解锁；
- [ ] 已通过离线交易确认演练器的正常与拒绝情景；
- [ ] 已在第二个干净配置文件恢复 A，并通过自动同步或手动添加恢复 B；
- [ ] 已完成脱敏记录；
- [ ] 单元检查达标；
- [ ] 没有使用真实资金、主网、DApp、token 授权或外部签名。

公共 Sepolia 收发是可选加练，不纳入上述通过条件。
